# 2026-05-06 火山引擎通用语音 PoC 设计

## 背景

当前 v3 板端与云端链路已进入稳定使用状态，客户连续约两周每天 6 到 10 次使用，当前不是救火状态。

五月待办里，现有佛像方案包含 OTA、首字延迟优化、唤醒与打断、多轮持续对话、RAG 爬虫、WiFi 联网、尾音淡出、用户记忆、降噪与回声消除等多项工作。其中首字延迟优化、唤醒、打断、多轮和音频算法都可能被新的云端语音架构影响。

因此当前不应直接投入 v3 架构级大改。优先做火山引擎通用大模型语音链路 PoC，用短周期实测判断它是否值得替代或部分替代 v3。

## 目标

用 3 到 5 天完成火山引擎通用大模型语音链路 PoC，回答一个核心问题：

> 火山引擎通用方案是否明显优于当前 v3，且是否适合接入 ESP32-S3 / ESP-VoCat v1.2。

第一阶段只验证通用大模型，不验证“浪漫模型”。

## 非目标

- 不在第一阶段替换现有 v3 生产链路。
- 不直接改板端 v24 音频主链路。
- 不直接做 v3 的 ASR 流式 Opus 上行大改。
- 不直接实现用户专属记忆。
- 不直接实现 RAG 爬虫全自动入库。
- 不把公司账号密码写入仓库、日志、文档或命令历史。

## 方案取舍

推荐路线：

1. 保持 v3 现网稳定，只做必要维护。
2. 开一个火山引擎通用语音 PoC 支线。
3. 用同一批佛学问题和同一套延迟指标对比 v3 与火山方案。
4. 如果火山方案明显更好，再规划云端大改。
5. 如果火山方案不足，再回到 v3 首字延迟与持续对话路线。

暂缓路线：

- v3 首字延迟架构级大改。
- 官方唤醒词、用户打断、多轮持续对话。
- 非官方定制唤醒词。
- 降噪与回声消除深度算法。

可并行但不抢优先级的低风险项：

- OTA 样机方案调研。
- 尾音淡出。
- WiFi 联网模块需求整理。
- RAG 知识库爬虫与清洗规则设计。

## PoC 验证维度

### 1. 接口与鉴权

- 明确火山引擎通用大模型语音能力的实际接口形态：
  - WebSocket
  - HTTP streaming
  - RTC
  - SDK only
- 明确是否支持低延迟音频输入输出。
- 明确鉴权方式是否适合服务端代理，不让 ESP32-S3 直接持有云厂商密钥。

### 2. ASR 准确率

必须用佛学专有词测试：

- 阿弥陀佛
- 四十八愿
- 净土宗
- 无量寿经
- 金刚经
- 般若
- 慧远
- 善导
- 东林寺

结论必须区分：

- ASR 听错
- RAG 没召回
- LLM 不会答
- TTS 或音频链路问题

### 3. 延迟

至少记录：

- 录音结束到首个 ASR 结果
- 首个模型 token / 文本片段
- 首个 TTS 音频字节
- 端到端首播延迟
- 完整回答耗时

火山方案必须和当前 v3 以同样口径对比，不能只看云厂商控制台主观体验。

### 4. 对话体验

验证：

- 半双工快速切换是否足够接近全双工体验。
- 是否支持用户打断。
- 是否支持连续多轮，不要求每次 touch。
- 是否能注入官方提示词。
- 是否能支持后续非官方唤醒词或昵称方案。

### 5. 与现有 RAG 的关系

火山通用模型不能直接替代佛学知识库。

PoC 必须验证至少一种集成方式：

- 火山负责实时语音与通用模型，现有服务负责 RAG 检索和提示词组装。
- 或火山模型作为 LLM provider，保留现有 RAG ingest、索引和 ASR 热词维护策略。

必须保留经验：

- 新增佛学专题词时，RAG 和 ASR 热词要一起更新。

### 6. 板端适配风险

必须确认：

- ESP32-S3 是否能稳定承载目标协议。
- 若火山只适合 RTC，是否需要云端代理转换为板端更容易消费的 HTTP/WebSocket 音频流。
- 是否支持 Opus 或 PCM。
- 长连接断线重连和弱网行为如何处理。

## 成功标准

PoC 成功不等于上线。只有满足以下条件，才进入火山云端大改规划：

1. 佛学专有词 ASR 不明显弱于当前 DashScope 热词方案。
2. 首播延迟明显优于当前 v3，或在打断/多轮体验上有明显优势。
3. 能保留或接入现有 RAG，不导致佛学回答失控。
4. 接口形态能通过云端代理稳定服务 ESP32-S3。
5. 成本、鉴权、稳定性没有明显阻断项。

如果以上条件不满足，回到 v3 路线，优先做：

1. OTA 样机。
2. v3 首字延迟优化。
3. 持续对话与打断。
4. 尾音淡出等低风险体验优化。

## 交付物

- 火山引擎通用语音接口可用性记录。
- v3 vs 火山方案对比表。
- 一组佛学测试问题的 ASR / RAG / LLM / TTS 分层结果。
- 是否进入火山云端大改的结论。
- 如果进入大改，另起实施计划，不直接在 PoC 文档中展开。
